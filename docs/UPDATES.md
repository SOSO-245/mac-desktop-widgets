# 软件更新

六款 Mac 工具右键菜单栏 → 软件更新。默认每天自动检查；有新版本时出现绿色小点，不抢焦点。可手动检查，也可勾选“自动下载并在退出时安装”；自动安装默认关闭。应用须运行且可访问 GitHub，休眠和网络不可用会延后，不添加维护定时任务。

这是首次支持更新的版本，旧版需要先安装一次。更新只替换应用包，保留本机配置、钥匙串项目、生日、日程、卡片位置和登录启动偏好。应用使用原 bundle identifier；不要同时运行不同目录的多个副本。

## 验证与限制

采用固定 Sparkle 2.10.0；更新清单 XML 与 ZIP 均使用 Ed25519 签名，应用内嵌公钥，要求提取前验证。签名失败不会替换旧程序。私钥只留在发布者的钥匙串，不在仓库、构建包或日志中。关闭 Sparkle 系统信息上传。

目前仍为临时应用签名，未完成 Developer ID 签名与 Apple 公证。更新签名验证发行来源，并不能让 macOS 永久保留其他应用共享数据权限；系统仍可能要求重新确认已有权限。工具不会代授权，也不改 VPN、代理、路由或节点。

## 手机

[Scriptable 版](../projects/codex-resets/scriptable)需要先手动安装 1.1.0。以后在 Scriptable 运行脚本 → 检查脚本更新，确认后下载。校验固定 GitHub 来源、版本和 SHA256，保留旧脚本备份，失败恢复原文件。手机使用 HTTPS 清单与摘要校验，不宣称具有 Mac 版的独立 Ed25519 验签；组件后台不自动覆盖脚本。

## 发布维护

1. 修改公开源码并更新版本，从脱敏工作树执行 `scripts/build_release.py`。
2. 执行源码、包内容、签名和版本检查。不要使用已安装应用重新打包；禁止复制用户配置、实体映射和缓存。
3. 使用 `scripts/sign_release.py --assets <输出目录> --tag <新标签> --account <本机签名账号>` 生成各应用 feed 和手机清单。只读取钥匙串，不导出私钥。
4. 发布对应标签源码与 GitHub Release 附件，保持文件名和签名一致。修改 ZIP 后必须重新签名；不可将没有实际附件的 feed 当作已发布。
5. 新维护者须使用自己的签名账号、公钥和发行地址，不应继续使用本仓库公钥发布自己的构建。

`shared/updater` 是共用实现，各项目持有同版本副本。构建依赖归档固定 SHA256；完整源码仍可独立构建。集成测试见 `shared/updater/Tests`，使用独立临时应用和测试钥匙串账号，不触及六款真实应用。
