# 软件更新

六款 Mac 工具从菜单栏“设置…”进入“软件更新”或“更新与版本”页。默认每天自动检查；有新版本时出现绿色小点，不抢焦点。可手动检查，也可勾选“自动下载并在退出时安装”；自动安装默认关闭。应用须运行且可访问 GitHub，休眠和网络不可用会延后，不添加维护定时任务。

自动更新从 2026.10.25-r6 起提供；更早且未带更新功能的旧版需要先手动安装一次。更新只替换应用包，保留本机配置、钥匙串项目、生日、日程、卡片位置和登录启动偏好。应用使用原 bundle identifier；不要同时运行不同目录的多个副本。

本轮版本为家庭概览 2.3.9、万年历 1.4.7、Codex 重置 1.4.1、VPN 实时卡片 1.4.2、Nikki 实时卡片 1.3.2、Mac 实时监测 1.2.5；另附桌面工具箱 1.0.0（目前手动更新）。六款保持独立运行，保留原连接、卡片位置和显示偏好。

## 验证与限制

采用固定 Sparkle 2.10.0；更新清单 XML 与 ZIP 均使用 Ed25519 签名，应用内嵌公钥，要求提取前验证。签名失败不会替换旧程序。私钥只留在发布者的钥匙串，不在仓库、构建包或日志中。关闭 Sparkle 系统信息上传。

目前仍为临时应用签名，未完成 Developer ID 签名与 Apple 公证。更新签名验证发行来源，并不能让 macOS 永久保留其他应用共享数据权限；系统仍可能要求重新确认已有权限。更新过程不会代授权、启停 VPN、切换节点或修改路由；VPN/Nikki 的节点选择仍需用户在业务窗口明确操作。

## 手机

[Scriptable 版](../projects/codex-resets/scriptable)需要先手动安装 1.1.0。以后在 Scriptable 运行脚本 → 检查脚本更新，确认后下载。校验固定 GitHub 来源、版本和 SHA256，保留旧脚本备份，失败恢复原文件。手机使用 HTTPS 清单与摘要校验，不宣称具有 Mac 版的独立 Ed25519 验签；组件后台不自动覆盖脚本。

本轮手机脚本没有变化，保留原有 1.1.0 清单与下载标签，不随 Mac 发布重写。只有明确发布手机脚本时，才在签名准备命令中使用 `--include-scriptable`；版本从脚本内的 `SCRIPT_VERSION` 读取。

## 发布维护

1. 修改公开源码并更新版本，运行 `python3 scripts/sync_shared_settings.py` 同步共用副本后，从脱敏工作树执行 `scripts/build_release.py`。完整 Xcode 是正常构建路径。受控 CLT 构建须使用已固定 SHA256 的公开安装包作为资源来源，复核系统小组件相关实现与元数据兼容性，只重编公开主程序；记录来源、源码摘要和保留的 WidgetKit 负载，不使用已安装应用。
2. 执行源码、包内容、解压后严格应用签名和架构检查。核对主程序与小组件的版本/build 一致，更新公钥与 feed 对应，并确认本机签名账号的公钥与应用内嵌公钥一致；禁止导出私钥或复制用户配置、实体映射和缓存。最终 ZIP 不得再改动。
3. 先执行 `python3 scripts/sign_release.py --assets <输出目录> --check-only`，只读检查六款 manifest、ZIP 摘要/CRC、身份、更新配置及主程序/小组件版本；此模式不调用签名工具、不访问钥匙串、不改清单，也不替代第 2 步的应用签名与实机检查。
4. 使用 `python3 scripts/sign_release.py --assets <输出目录> --tag <新标签> --account <本机签名账号>` 生成六款 Mac feed。私钥仅由 Sparkle 工具从钥匙串使用，不导出。脚本先验证全部包，再签名并验证临时 XML，全部成功后替换更新清单；默认保持手机 feed 不变。仅手机也有明确发布内容时加 `--include-scriptable`。
5. 先上传对应 GitHub Release 附件并核对下载摘要，再公开指向它们的更新清单与标签源码；保持文件名和签名一致。修改 ZIP 后必须重新签名，不可将没有实际附件的 feed 当作已发布。发布前将 README/CHANGELOG 的待发布状态更新为实际标签与验证结果。
6. 新维护者须使用自己的签名账号、公钥和发行地址，不应继续使用本仓库公钥发布自己的构建。

`shared/settings` 维护共用设置、菜单栏、浮窗和更新界面，各项目持有由 `scripts/sync_shared_settings.py` 同步的副本。构建依赖归档固定 SHA256；完整源码仍可独立构建。更新集成测试仍见 `shared/updater/Tests`，使用独立临时应用和测试钥匙串账号，不触及六款真实应用。
